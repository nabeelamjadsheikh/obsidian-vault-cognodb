Reindexing crossed the threshold from "technically slow" to "I have started avoiding saving", which is the only threshold that has ever caused me to fix a performance problem.

The numbers: 1.4 seconds on save at seven hundred notes, up from 200ms two years ago. Nothing regressed — the vault grew and the context extraction got more careful. The dirty-set rewrite has been sitting half-designed in [[Incremental Indexing]] since last spring, and today it finally cost less to build than to keep tolerating. Down to about 25ms on the normal path.

- [x] Dirty-set patching, with the previous-parse bookkeeping
- [x] Full rebuild on every process start, no exceptions
- [x] `--verify` mode that rebuilds to scratch and diffs
- [ ] Run verify weekly for a month before trusting it
- [ ] Delete the old full-reindex path once verify has been clean four times

I want to record that the delay was correct. Building this in 2024 would have been optimising a non-problem, and the cost — a consistency checker I now own forever — would have been paid for two years of benefit I did not need. The trigger was behavioural, not a metric.

The consistency risk is entirely downstream of storing context sentences on the edge, per [[Backlink Index Design]], because a body edit that changes no links still changes the index. Worth it, but it is the reason the naive link-hash comparison does not work.

Fast reindexing immediately made the ranking work in [[Ranking Search Results in a Vault]] feel different — recency weighting is only meaningful if "recent" means seconds ago. Two features that were each fine became good together, which I did not anticipate.

Also rebuilt the global view out of curiosity and confirmed everything in [[Graph Layout Experiments]] again: prettier at 700 nodes, no more informative. I will stop doing this.

Meanwhile Lantern sat untouched all week, and [[Lantern — Open Questions]] has not moved since the retro. Tooling work is comfortable in a way that product work is not, which is a question I should put through [[Project Postmortem Template]] before it becomes the answer.
